# 车端 Agent 从 OpenClaw 迁移到 PicoClaw：面试题单与两周复盘计划

适用方向：车端 Agent 引擎迁移与性能优化。编制日期：2026-11-20。

项目背景：车端 Agent 从 OpenClaw 迁移到 PicoClaw，降低资源占用并优化执行链路。新提供的进展材料记录一期已在 OTA 9.3 内测 1 上线，内存均值降低 88.8%、CPU 均值相对降低 87.0%、端到端平均耗时降低 25.0%；这是团队整体效果，测试口径和个人贡献仍需补充。二期规划、早期评估与一期成果应分别说明，不使用已弃用的链路资料。

**最新主练题单：** [车端 Agent 面试模拟问题与项目回答](车端Agent_面试模拟问题与项目回答.md)。按面试官视角设计 24 道问题，再结合项目材料提供口述回答、继续追问和待补证据；两周复盘优先使用该文件。本文件保留为 42 题扩展知识索引。

## 1. 使用口径与准备优先级

- 共 **42 题**：P0 18 题、P1 18 题、P2 6 题。
- **P0：核心必会。** 重点是迁移动机与选型、资源和延迟分析、能力兼容及验证，能结合自己的实现与测量证据说明。
- **P1：高频补强。** 补齐上下文、业务效果、车控安全与工具治理。安全是迁移验收的硬约束；这里的复习顺序不表示工程上可以后做。
- **P2：按岗位补充。** 结合招聘要求和实际技术栈调整。若有笔试，从第一天起每天增加 20–30 分钟算法练习。
- 题目来源分为“题库代表题改写”“车端模拟题”“项目追问”“迁移项目模拟题”。后三者是为本岗位新增的练习，不是采集原题；参考答案仅提供相关知识，不一定直接回答车端问题。
- 覆盖篇数来自 109 篇已采集面经；主题允许重叠，不是全行业频率，也不是 OpenClaw/PicoClaw 迁移专项统计。

## 4. 每道题的复盘模板

```text
题号 / 题型：
一句话结论：
前提与需要澄清的信息：
正常流程 / 核心机制：
模型、Runtime、执行端各自职责：
关键异常及处理：
方案取舍：
迁移前后差异 / 自己的实际实现与个人贡献：
验证方法 / 真实证据 / 对照条件：
相关题库入口：
待核实的问题：
本次评分 / 下次复测：
```

原理题可省略场景字段；项目深挖题必须写个人贡献；场景题必须写异常和验证。未实现的机制标注“设计建议”，未测量的数据标注“待测”，不要把参考答案当个人经历。

## 5. 熟练度与复测规则

| 分数 | 状态 | 下一步 |
|---|---|---|
| 0 | 不会，或关键事实尚未核实 | 查参考和现行源码，记录事实边界 |
| 1 | 能背结论，解释不清机制 | 补流程与一个反例 |
| 2 | 能解释机制，但异常或证据不足 | 加两轮异常追问，补验证方法 |
| 3 | 能讲流程、边界、取舍与证据 | 进入混合模拟 |

- 次日重测 0–1 分题；3 天后复测 2 分题；一周后随机抽测 3 分题。
- P0 目标：全部至少 2 分，其中迁移选型、资源基线、延迟归因、兼容验证四个方向至少各有一题达到 3 分；P1 安全题必须能明确最终执行约束。
- 闭卷复述目标：原理题 1–2 分钟，项目题 3 分钟，场景题 5 分钟，加两轮追问。
- 场景设计的评价重点是前提、流程、异常、取舍与可验证性；项目成果必须有真实证据支撑。

## 6. 一轮结束应形成的材料

- 项目介绍主线：资源与耗时问题 → 基线和瓶颈 → 选型取舍 → 迁移与优化 → 能力兼容 → 验证收益与代价。
- 一张新旧执行链对比图；标注每项变化和个人贡献。
- 一份能力矩阵：模型接入、工具、流式事件、会话、记忆、取消、权限、恢复及当前不支持项。
- 一份资源与延迟对照表：启动时间、常驻/峰值内存、CPU、队列、端到端 P50/P95、任务成功率；注明设备、版本、模型、负载、样本量及冷热条件。
- 三张异常时序图：超时但可能已执行、用户取消/改指令、多步任务部分失败。
- 一份迁移验收与回滚说明；验证新旧系统不会同时执行真实副作用。影子对照默认只比较决策或使用模拟工具，不向真实车控双发。
- 两个真实案例：一个资源优化，一个链路耗时优化。若未完成或未测量，标注进展与验证方案，不写成已取得成果。
- 一份按题号维护的盲点清单，记录评分、证据位置和复测日期。

## 7. 性能复盘中必须分清的边界

- 包体或镜像大小、运行时常驻内存、峰值内存和 CPU 占用是不同指标，不能互相替代。
- 语言或框架名称不能单独解释收益；需定位依赖裁剪、执行路径、分配、并发或上下文等具体变化。
- 降低常驻内存不等于降低模型推理耗时；链路优化应说明减少了哪段等待或多少次模型调用。
- 优化前后保持对照条件；改模型、Prompt、网络或缓存的收益应与引擎迁移收益分别说明。
- 性能收益同时检查业务成功率、实际生效与安全回归，不能用省略必要检查来证明有效优化。
