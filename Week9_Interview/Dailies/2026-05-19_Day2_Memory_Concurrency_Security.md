## 🧠 模块 1：长期记忆写回 / 衰减 / 冲突消解（腾讯 Q5）

### 问题
你怎么设计 Agent 的长期记忆写回策略、衰减策略和冲突消解？

### 核心答案

**写回策略**：
- 只保存高价值、稳定的信息（用户偏好、身份属性、长期目标、反复出现的业务事实）
- 结构化抽象存储，不存原文
  - 例：把"用户更喜欢用 Python" → 存入 profile.preferred_language = "Python"

**衰减策略**：
- 短期热点：高优先级，但随时间衰减
- 稳定长期偏好：低频更新，不轻易删除

**冲突消解**：
- 结合时间戳 + 来源可信度 + 置信度判断
- 新的高置信信息：直接覆盖旧的低置信内容
- 低置信内容：只作备选，不能直接覆盖

**进阶设计**：
- 事件流 + 物化视图
  - 所有记忆先作为事件写入
  - 再异步聚合到 profile
  - 支持审计和回滚

## 🧠 模块 2：并行 Tool Calling 的依赖管理与一致性（腾讯 Q6）

### 问题
你怎么做并行 Tool Calling，既提升吞吐又保证一致性与可回放？

### 核心答案

**关键原则**：
- 只有独立的工具才能并行（天气查询 + 汇率查询 → 可以同时）
- 有依赖关系的必须串行（Tool B 依赖 Tool A 的输出 → B 等 A 完成）

**状态管理**：
- 工具不直接修改共享状态，结果写入临时观察区
- 由协调器统一合并成完整 DAG
- 每次调用记录：trace_id + step_id + 输入参数 + 输出结果 + 耗时

**失败处理**：
- 失败以单工具粒度重试，不是整体丢弃
- 有副作用的操作（发消息、创建订单）必须做幂等
  - 加 nonce 或时间戳，防止重试造成重复写入

## 🧠 模块 3：Agent 记忆三类及混用风险（腾讯 Q11）

### 问题
Agent 的 Memory 一般怎么做？

### 三类记忆

| 类型 | 内容 | 更新频率 |
|------|------|---------|
| 短期操作记忆 | 当前上下文、上一工具返回什么、执行到规划哪一步 | 极高 |
| 任务记忆 | 相似任务历史案例、常见失败模式 | 中 |
| 长期偏好记忆 | 用户习惯、系统配置 | 低 |

**注意事项**：
- 三者更新频率和读取优先级不同，混在一起会乱
- 记忆最好结构化，而非全部做成自然语言总结
  - 全是文本 → 检索时把过期信息和有效信息混在一起

**最大风险**：
> 记忆系统最大的风险不是"记不住"，而是"记住了不该记的"

## 🧠 模块 4：Prompt Injection 五层防护（腾讯 Q12）

### 问题
Prompt Injection 在 Agent 场景里怎么防？

### 定义
在用户输入或外部文档中注入恶意指令，诱导模型忽略既定规则。

**Agent 场景的危险性**（比普通 LLM 更严重）：
- 生成错误文本 → 误导工具调用 → 越权操作 → 触发真实业务操作

### 五层防护

```
① 角色与优先级隔离
   外部知识不能覆盖系统规则

② 文档即证据，而非指令
   搜索结果/RAG 文档 = 证据，不是可执行指令

③ 白名单与参数校验
   所有工具调用必须使用白名单名称和校验过的参数
   高风险操作需要二次确认

④ 可追溯与可回滚
   输出和调用链可追溯，出错可回滚

⑤ 输入清洗与风险分级
   明显的越权或诱导内容直接拦截
```

**核心原则**：
> 核心不是靠一句 prompt 防住，而是靠系统设计让模型即使被诱导，也没有越权能力

## 🧠 模块 5：长任务死循环 / 无限推理的终止机制（腾讯 Q15）

### 问题
长任务场景里，怎么避免 Agent 无限推理或者死循环？

### 两类策略

**策略一：状态机 + 终止条件**
- 强制限制：最大推理步数 + 工具调用次数 + token 消耗 + 执行时长
- 明确触发条件：完成 / 失败 / 用户反馈

**策略二：重复动作检测**
- 连续几步重复使用同一工具 + 产出相似 / 无新证据
- → 强制终止，返回阶段性结论
- 避免无意义循环
