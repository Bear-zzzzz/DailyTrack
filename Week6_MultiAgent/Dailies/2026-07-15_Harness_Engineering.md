## 🧠 当前掌握

### 统一框架
- Prompt Engineering：单次调用里的指令设计
- Context Engineering：单次调用里的信息组织
- Harness Engineering：跨轮次、跨工具、跨 Agent 的完整运行治理

### 约束驱动思维
- 上下文有限 → 压缩、检索、记忆分层
- 模型非确定 → schema、验证、fallback、重试
- 外部世界动态 → 持久化、幂等、可恢复执行、编排

### 系统分层视角
- 上下文治理：决定这一轮给模型什么
- 状态持久化：保存不能丢的状态，支持恢复
- 编排与控制流：决定步骤、重试、终止、串并行
- 工具系统：接入外部能力
- 验证与安全：检查结果、兜底和护栏

### 上下文治理视角
- context 是工作台，不是仓库
- 上下文治理要主动做，不能等快爆了才压缩
- 优先使用低成本减负手段，摘要只是最后兜底

### 状态持久化视角
- 关键状态必须外部化，不能只依赖瞬时 context
- 文件系统状态的核心价值是可恢复、可共享、可审计、可寻址
- 记忆系统既要会存，也要会选择、会召回、会标记新鲜度

### 多 Agent 编排视角
- 单 Agent 的两大天花板是长任务失控和自我评估偏差
- 生成与评估应拆分，避免同一 Agent 对自己过宽容
- Planner 定目标，Generator 做实现，Evaluator 做验收
- Sprint Contract 用于在实现前先对齐完成定义和验收标准
- Agent 间优先通过文件通信，后台辅助任务可用 Fork 隔离

### 工具系统设计视角
- 工具设计的重点不是能否调用，而是调用是否可控、可恢复、可并发、可审计、可节省上下文
- 并发安全是语义属性，不是工具类别属性
- 工具结果预算应在工具层声明，超限后自动落盘
- API 输入视图与可观测视图可以分离，以兼顾缓存稳定性和调试完整性
- 错误信息不能静默吞掉，错误本身也是上下文

### 安全与可靠性视角
- 安全与可靠性是执行边界，不是最后补上的附加功能
- 熔断用于防止异常重试和故障级联
- 安全应采用防御纵深，而不是依赖单点检测
- 模型决策和真实执行之间应有 Policy Gateway 作为硬性拦截层
- 可靠性的核心关键词：可恢复、幂等、一致

## 🧾 一页版总结（复习 / 面试）

### 1. 三层关系
- Prompt Engineering：单次调用里的指令设计
- Context Engineering：单次调用里的信息组织与取舍
- Harness Engineering：让 Agent 在跨轮次、跨工具、跨 Agent 执行中稳定运行的系统层治理
- 关系：Prompt 是写这一跳，Context 是喂这一跳，Harness 是把整个系统跑稳

### 2. 三大根本约束
- 上下文有限：风险是关键状态丢失、决策链断裂、接近上限时模型退化；机制是上下文治理、压缩、外部化、检索、记忆分层
- 模型非确定：风险是工具选择错误、参数错误、格式错误、推理漂移；机制是 schema、验证、fallback、重试、评估器
- 外部世界动态变化：风险是状态漂移、外部系统失败、任务中断、重复执行产生副作用；机制是持久化、可恢复执行、幂等、超时/重试、编排控制流

### 3. Harness 的五层结构
- 上下文治理：决定这一轮给模型什么
- 状态持久化：保存不能丢的状态，支持恢复
- 编排与控制流：决定步骤、路由、串并行、重试、终止条件
- 工具系统：接入外部能力，重点是可控、可恢复、可并发、可审计、可节省上下文
- 验证与安全可靠性：负责结果校验、权限、安全护栏和故障兜底

### 4. 重点易错点
- context 是工作台，不是仓库；要主动治理，不能等快爆了再压缩
- 五层压缩梯级：外置 → 删除 → 占位 → 折叠 → 摘要兜底
- 关键状态必须外部化到稳定介质，核心价值是可恢复、可共享、可审计、可寻址
- 新鲜度是在提醒“这条记忆可能过期，需要验证”，不是简单降权
- Generator / Evaluator 分离的核心，是拆开“产出”和“严格挑错”两个冲突目标
- 并发安全 = 当前具体调用的语义属性，不是工具标签
- 语义分组 + 批次清空 = 按原始顺序切成多批安全调用，不是先把所有安全调用一次跑完
- 错误本身也是上下文，失败信息必须回流给 Agent

### 5. 安全与可靠性
- 安全与可靠性是执行边界，不是最后补上的附加层
- 熔断：阻止异常重试和故障级联
- 防御纵深：模式匹配做表层筛查，AST/语义分析看真实意图，权限规则决定允不允许执行，沙盒限制最坏后果
- Policy Gateway：模型决策不等于执行许可，所有工具调用都应经过硬规则网关
- 可靠性三件套：可恢复、幂等、一致

### 6. 面试短答模板
> Prompt Engineering 解决的是单次调用里怎么写指令，Context Engineering 解决的是单次调用里给模型什么信息、怎么组织信息，而 Harness Engineering 更上一层，它解决的是 Agent 在跨轮次、跨工具、跨 Agent 执行任务时，怎么稳定运行。因为真实 Agent 会遇到上下文有限、模型非确定、外部世界动态变化这三大约束，所以必须通过上下文治理、状态持久化、编排控制流、工具系统、验证和安全可靠性等机制，把整个系统跑稳。
