## 🧠 模块 1：6 种主流 Agent 架构（腾讯 Q7）

### ReAct
- reason + act，思考 → 调工具 → 观察 → 继续思考
- 适合：边界清晰的单步任务

### Plan-and-Execute
- 先规划完整动作序列，再按步执行
- 比 ReAct 更稳定，适合长任务

### Router 模式
- 先做任务分类，再路由给不同子 Agent 或工具链
- 适合：入口统一、出口多样的场景

### Workflow + Agent
- 固定流程里嵌局部自主决策
- 常见于线上业务（稳定性优先）

### Supervisor 模式
- 主 Agent 拆解任务并分派给多个子 Agent
- 适合：复杂任务 + 子任务能力差异大

### Blackboard 模式
- 多个 Agent 通过共享状态协作
- 注意：纯点对点自由协作线上极少见，因为难以管理

## 🧠 模块 2：MCP / A2A / Function Calling 三者区别（腾讯 Q8）

### 三者定义

| | Function Calling | MCP | A2A |
|---|---|---|---|
| 本质 | 调用一个函数 | 暴露一组标准能力 | 多智能体协作完成任务 |
| 层次 | 模型↔宿主应用 | 协议层（资源/能力暴露） | Agent↔Agent |
| 关注点 | 调用哪个函数 | 能力发现与标准化调用 | 任务/状态/结果的交换 |

### 选型建议
```
单应用工具使用          → Function Calling
多模型/IDE 共享工具资源  → MCP
复杂多 Agent 工作流      → A2A
```

## 🧠 模块 3：Agent 评估四层框架（腾讯 Q13）

### 问题
你怎么评估一个 Agent 系统的效果？

### 四层框架

```
Layer 1：回答质量层
  准确性 + 完整性 + 是否基于证据

Layer 2：工具质量层
  选工具是否正确 + 参数是否正确 + 调用是否成功

Layer 3：任务质量层
  一次会话是否完成目标 + 是否需要额外追问 + 是否需要人工接管

Layer 4：系统质量层
  耗时 + 成本 + token 消耗 + 错误率 + 稳定性
```

**RAG 系统额外评估**：召回命中率 + rerank 效果 + 答案引用质量

**核心观点**：
> Agent 不是单个模型的分数，而是整条链路的分数

**回放评测**（加分项）：
- 把真实脱敏任务按原始环境重放
- 静态 benchmark 只说明"会做题"
- 回放才能看出动态环境里"会不会犯蠢"

## 🧠 模块 4：线上选错工具的排查 5 步法（腾讯 Q14）

### 问题
线上发现 Agent 经常选错工具，你怎么排查？

### 5 步排查顺序

```
Step 1：检查 tool description 和 schema 设计
  边界是否模糊？参数能否区分场景？

Step 2：检查 skill routing 层
  是否一次性塞了太多候选工具，导致噪音竞争？

Step 3：检查 prompt 和 few-shot 示例
  是否有误导性引导？system prompt 最近是否被改过？

Step 4：回放 trace
  选到这个工具之前的步骤
  历史记忆是否污染了当前判断？

Step 5：检查用户输入
  输入是否存在矛盾？
  模型推理过程是否有二次校验？
```

**核心观点**：
> 排查不是看最后一步，而是理解候选集的来源、模型为什么选它、执行前是否有校验

## 🧠 模块 5：高并发限流 / 降级 / 幂等设计（懂车帝 Q2）

### 问题
系统里有高并发场景，你会怎么设计限流、降级和幂等？

**核心观点**：
> 平均延迟不是问题，真正的问题是少数慢请求可能拖垮整个请求链

### 多层限流

```
Layer 1：入口层     用户级、租户级限流
Layer 2：任务调度层  按任务队列隔离
Layer 3：工具层     并发池控制
Layer 4：模型层     token 预算 + 超时恢复
```

### 幂等设计

- 写操作（发通知、审批、更新状态、创建工单）必须给每次执行唯一 request_id / task_id
- 重复执行时识别并返回历史结果，不重复写入
- 否则：模型一次超时重发 → 造成重复写入

## 🧠 模块 6：优化 Agent 系统从哪里下手（懂车帝 Q4）

### 问题
如果让你优化一个 Agent 系统，你通常先从哪里下手？

**原则**：不会一上来就换模型或改 prompt，先拆系统瓶颈。

### 三类问题分类

```
① 规划问题
  路径选错，如两步的任务走了六步

② 执行问题
  工具调用成本高、重试过多、失败转成功比低

③ 观察问题
  模型输出的信息噪音大或散乱，导致每步判断不准确
```

**优化方向**：
- 性能优化：工具调用频次、上下文长度
- 效果优化：错误聚类分析（如"状态过早进入执行"、"证据不足导致无追问"）
- 有效优化通常是**缩短错误链**，而非孤立改进某一点
